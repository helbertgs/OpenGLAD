# Contributing to OpenGLAD

Thank you for taking the time to contribute. This document explains how to get started.

## Ways to Contribute

- Report bugs via GitHub Issues: https://github.com/helbertgs/OpenGLAD/issues
- Suggest improvements or new features
- Submit pull requests with fixes or enhancements
- Improve documentation

## Getting Started

1. Fork the repository and clone it locally.
2. Create a branch from `main`:
```sh
   git checkout -b feature/your-description
```
3. Make your changes.
4. Build and verify:
```sh
swift build
```
5. Open a pull request against main.

## Guidelines

### Code

- Keep changes focused — one concern per pull request.
- The C files (gl.c, gl.h, khrplatform.h) are generated by GLAD 2 and should not be edited manually.
If regeneration is needed, update the configuration in the GLAD 2 generator (https://gen.glad.sh) and replace the generated files.
- Swift tooling changes (e.g., Package.swift, module.modulemap) are allowed.

### Commits

Use Conventional Commits:

```markdown
feat: add support for OpenGL 4.1
fix: correct modulemap export for khrplatform types
chore: update GLAD to 2.0.9
docs: clarify concurrency usage in README
```

### Pull Requests

- Describe what changed and why.
- Reference any related issue (e.g., Closes #12).
- Keep the diff minimal — avoid unrelated formatting changes.

### Reporting Bugs

Open an issue and include:
- Operating system and version
- Swift version (swift --version)
- Steps to reproduce
- Expected vs. actual behavior

## Security

For security-related issues, please follow the process described in [SECURITY.md](https://github.com/helbertgs/OpenGLAD/SECURITY.md).

## Code of Conduct
This project follows the [Contributor Covenant](https://github.com/helbertgs/OpenGLAD/CODE_OF_CONDUCT.md). Please be respectful and constructive.
